# v0.1.0 Release Preflight Checklist

## Build and runtime verification

- [ ] Run `npm.cmd test`.
- [ ] Run `cargo test` from `src-tauri`.
- [ ] Run `npm.cmd run tauri:build:windows`.
- [ ] Install the generated Windows installer on a clean Windows x64 test environment.
- [ ] Verify that compression works without a user-installed FFmpeg or ffprobe on `PATH`.
- [ ] Verify that ffprobe and both FFmpeg encoding passes do not open a black CMD window.
- [ ] Verify the UI progression: video analysis → compression → completion.
- [ ] Verify compression with an audio stream and without an audio stream. For a multi-audio MP4, verify that only its first audio stream is included in the output.
- [ ] Verify cancellation during the first pass, between the first and second pass, during the second pass, and immediately before FFmpeg starts. Verify that the next compression starts normally.
- [ ] Verify the output does not overwrite an existing file.
- [ ] Verify the completed MP4 plays successfully and its size is at or below, or acceptably close to, the requested target under the documented safety-margin behavior.
- [ ] Verify the completed screen can open both the output file and its folder.

## FFmpeg GPL distribution assets

This is an operational checklist, not legal advice. Confirm the required distribution approach for the actual Release with the appropriate maintainers or advisers.

- [ ] Record the `ffmpeg -version` output from the exact binaries being released.
- [ ] Confirm the identifiers match this release's notice: `n8.1.2-44-g7c533d0f86-20260815`, source revision `7c533d0f86`, and BtbN artifact family `ffmpeg-n8.1-latest-win64-gpl-8.1`.
- [ ] Attach the Windows installer(s).
- [ ] Attach `THIRD_PARTY_NOTICES.md`.
- [ ] Attach an unmodified copy of the GNU GPL v3 or later license text (for example `GPL-3.0-or-later.txt`).
- [ ] Record the exact BtbN binary archive `ffmpeg-n8.1-latest-win64-gpl-8.1.zip`, its SHA-256 checksum, and the BtbN FFmpeg-Builds commit/ref used for this binary.
- [ ] Check out that recorded BtbN FFmpeg-Builds commit, run its `download.sh`, and archive the resulting `.cache/downloads` dependency source archives as a Release Asset.
- [ ] Attach the FFmpeg source for revision `7c533d0f86` with the dependency source archive. Include the matching BtbN `download.sh`, relevant `scripts.d` definitions, build configuration, and any source changes or `changes.diff`, where applicable.
- [ ] Do not treat the BtbN Release page's `Source code (zip)` asset as the corresponding source bundle: it is the FFmpeg-Builds repository snapshot, not the dependency source archives collected by `download.sh`.
- [ ] In the Release notes, state where the matching source bundle and GPLv3 text can be obtained.

No source archive is downloaded or generated by this repository. The Release manager must obtain, verify, and attach the matching artifacts before publication.
